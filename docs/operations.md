# Part A　開発・保守担当向け

## A-1. 前提ソフト

| ソフト | 条件 |
|---|---|
| Docker Desktop | 設定の「Use containerd for pulling and storing images」を**オフ**にする（A-4 (b) 参照） |
| Node.js | 24 |
| Git | 任意の最新版 |

## A-2. 初回セットアップ

```bash
npm ci
npx playwright install chromium
npm run env:start          # http://localhost:8888 が立ち上がる
npm run wp -- spc seed     # 仮データ（事例・料金・FAQ・職人）を投入。何度実行しても重複しない
```

- 管理画面は `http://localhost:8888/wp-admin/`（wp-env の既定は `admin` / `password`）。ローカル専用です。
- `wp spc seed` は本番（`WP_ENVIRONMENT_TYPE=production`）では実行できません。

## A-3. テストの実行

```bash
npm run test:php   # spc-core の PHPUnit（wp-env の tests-cli 内で実行）
npm run test:e2e   # Playwright（Chromium）
```

- `test:e2e` は `workers: 1`（直列実行）です。テストが1つの WordPress（設定・投稿）を共有し、一部のテストが設定を書き換えるため、並列にすると互いに干渉します。変更しないでください。
- 単一のテストだけ動かす例：`npm run test:php -- --filter Security`

## A-4. Windows でのトラブル対処

### (a) wp-env が「ネットワークに接続できない」と判定する

Node の DNS が `127.0.0.1` を向いてしまう端末（VPN ソフトなどの影響）で起きます。wp-env が最新の WordPress バージョンを取得できず失敗します。

`~/.wp-env/<ハッシュ>/wp-env-cache.json` を次の内容で作成してください（`<ハッシュ>` は `~/.wp-env/` 直下にあるプロジェクト用フォルダ名）。

```json
{"latestWordPressVersion":"7.1.3"}
```

wp-env がテスト用ライブラリ（WordPress PHPUnit）を取得できない場合は、手動で用意します。

1. `wordpress-develop` のタグ 7.1.3 から `tests/phpunit` だけをスパースクローンする（`git clone --filter=blob:none --sparse` の後に `git sparse-checkout set tests/phpunit`、タグ 7.1.3 をチェックアウト）。
2. 取得した `tests/phpunit` の中身を `~/.wp-env/<ハッシュ>/tests-WordPress-PHPUnit` に置く。

注意：`wp-env destroy` を実行すると、上記のキャッシュファイルとテスト用ライブラリは消えます。再度同じ手順が必要です。通常の作業で `destroy` は使わないでください（`env:stop` で止めるだけにします）。

### (b) Docker のイメージ展開でファイルが壊れる

Docker Desktop の設定 > General > **「Use containerd for pulling and storing images」をオフ**にして、Docker Desktop を再起動します。その後、イメージを取得し直してください。

### (c) メモリ不足でテストが不安定

PHP・E2E のテストが途中で落ちる、極端に遅い場合は、まず PC を再起動します。E2E は `workers: 1` のまま実行します。1回のタイムアウトはバグと決めつけず、同じテストを単独でもう一度実行して確認してください。

## A-5. 本番 `wp-config.php` の設定

```php
define( 'WP_ENVIRONMENT_TYPE', 'production' ); // 仮データの公開停止・非表示が有効になる
define( 'DISALLOW_FILE_EDIT', true );          // 管理画面からのテーマ・プラグイン編集を禁止
define( 'FORCE_SSL_ADMIN', true );             // 管理画面・ログインを常時 HTTPS に
```

- `DISALLOW_FILE_MODS`（管理画面からのプラグイン・テーマの追加／更新を禁止）は、より堅くなりますが、**管理画面からの更新もできなくなります**。採用するかは、ホスティングの運用（自動更新の有無）と合わせて、依頼元・保守担当で決めてください。TODO(仮)
- WordPress は `WP_ENVIRONMENT_TYPE` が未設定のとき `production` として扱うため、未設定でも仮データの公開停止・非表示は有効です。危ないのは、**ホスティングが `staging` や `development` を設定している場合**です（ステージング機能のあるホスティングでは自動で入ることがあります）。そのときは仮データがそのまま公開されます。本番では上のとおり明示的に `production` を設定し、`wp eval 'echo wp_get_environment_type();'` で `production` と表示されることを確認してください。

### spc-core のセキュリティ設定（`includes/security.php`、導入済み）

- XML-RPC を無効化し、`X-Pingback` ヘッダと RSD リンクを出さない
- 未ログインの REST `/wp/v2/users`（一覧・個別）は 401（他のREST経路とログイン済みの利用には影響しない）
- `?author=N` と投稿者アーカイブは、トップへ 301 で戻す
- ユーザー一覧のサイトマップ（`/wp-sitemap-users-1.xml`）を出さない
- oEmbed の応答に投稿者名・投稿者URL（`author_name` / `author_url`）を含めない
- `<meta name="generator">`（WordPress のバージョン）を出力しない

## A-10. 公開前の手順

**`wp spc launch-check` が通らない間は、公開してはいけません。**

1. **仮データの差し替え**
   - 管理画面：仮の事例・料金・職人・FAQ・固定ページ、LINE追加URL、LINE QRコード画像、ブランド名、GTM ID、一次返信の目安を本物に差し替える（Part B 参照）。
   - テーマ（保守担当が作業）：テンプレートに直接置いている仮の写真と仮の文言を差し替える。
     - 写真：トップ画像（繊維マクロ写真、`template-parts/lp/hero.php`）、対応メニューの写真4枚（`template-parts/lp/menu.php`）、職人と施工母体の作業風景（`template-parts/lp/craftsmen.php`）。メディアに登録した画像の添付ファイルIDを `inc/placeholders.php` の一覧（`spc_theme_placeholder_images()`）に入れると、仮枠の代わりに画像が出ます。
     - 下層ページの写真枠も同じ一覧に入っています（特殊シミ抜き `page-stain-removal.php`：`stain_work` / `stain_yellowing`、高級ダウン・コート `page-down-coat.php`：`down_detail` / `coat_detail`、職人・運営会社 `page-about.php`：`about_workshop` / `about_hands` / `about_equipment`）。差し替えは上と同じ手順で、`attachment_id` に添付ファイルIDを入れます。
     - QRコード：管理画面の「ブランド設定」で登録する（テーマの作業は不要）。
     - 文言：`grep -rn "TODO(仮)" wp-content/themes/spc-theme` で一覧を出し、依頼元に確認した文言に差し替えて、コメントも消す。確定の手順は A-11 (b) を参照。
   - `wp spc launch-check` は、管理画面の項目に加えて、テーマの仮の写真（種類 `theme_image`）、テーマの仮の文言（種類 `theme_copy`）、必要な固定ページの欠け（種類 `page_missing`）、必要な固定ページが下書きなど公開されていない状態（種類 `page_unpublished`）、必要な固定ページの本文に残った「（仮）」（種類 `page_placeholder_text`。仮データのチェックが付いたページは、通常の仮データの項目として出るので重ねては出ません）、QRコード画像の未設定（`line_qr`）、一次返信の目安の「（仮）」（`reply_time_note`）も一覧に出します。`theme_copy` に出るのは `spc_theme_placeholder_copy()` に登録した文言だけです。登録漏れがないか、上の grep でも確認してください。
2. **公開前チェック**
   ```bash
   wp spc launch-check
   ```
   残っている項目の一覧が出て終了コード1になる場合は、直して再実行します。**「公開前チェックに合格しました。」と表示されるまで**繰り返します。管理画面のサイトヘルス（管理バーの「仮データ N件」を押すと開きます）でも確認できます。
3. **GTM / GA4 の公開**：GTM コンテナで GA4 タグ・トリガー（`landing_view` / `line_click`）を設定し、プレビューで動作を確認してから公開する。
4. **noindex と Basic 認証を外す**（`wp spc launch-check` が合格してから行う）
   - noindex：WordPress 管理画面の「設定 > 表示設定」にある「検索エンジンでの表示」（「検索エンジンがサイトをインデックスしないようにする」）のチェックを外して保存する。
   - Basic 認証：サーバー（ホスティング）側で設定しているため、ホスティング側で解除する。方法はホスティングにより異なる。TODO(仮)
   - 解除後の確認：
     - ページのソースに `<meta name='robots' content='noindex…'>` が出ていない。
     - `/robots.txt` が全体を Disallow していない（`Disallow: /` だけになっていない）。
     - サイトが Basic 認証の入力画面なしで開く。
   - **`wp spc launch-check` が失敗している間は、公開してはいけません。**
5. **Search Console 登録**：プロパティを追加し、サイトマップ（`/wp-sitemap.xml`）を送信する。

## A-11. 下層ページの保守

### (a) スラッグ別テンプレート（スラッグを変えない）

下層ページは、固定ページのスラッグでテンプレートが決まります。**スラッグを変えると専用のテンプレートが当たらなくなり（ページは消えず、共通の表示になります）、公開前チェックに `page_missing`（必要な固定ページがありません）と出ます。** 管理画面でスラッグ（パーマリンク）を変更しないでください。

| URL | テンプレート |
|---|---|
| `/stain-removal/` | `page-stain-removal.php` |
| `/down-coat/` | `page-down-coat.php` |
| `/price/` | `page-price.php` |
| `/about/` | `page-about.php` |
| `/guide/` | `page-guide.php` |
| `/legal/` | `page-legal.php`（子ページの一覧） |
| `/legal/terms/`、`/legal/tokushoho/`、`/legal/privacy/` | 共通の `page.php`（親 `/legal/` の子ページ。専用テンプレートはありません） |
| `/cases/`、事例詳細 | `archive-spc_case.php`、`single-spc_case.php` |

- 必要な固定ページの一覧は spc-core の `spc_required_pages()` が持っています。ゴミ箱に入れた場合も `page_missing` になります。下書き・非公開などで公開されていない場合は `page_unpublished`、本文に「（仮）」が残っている場合は `page_placeholder_text` です。
- 共通部品は `template-parts/`（`page-header`、`page-notes`、`breadcrumbs`、`staff-list`、`price-steps`、`sections/*`）にあります。

### (b) 仮文言の確定手順

下層ページの文章のうち、依頼元の確認が済んでいないものは `spc_theme_placeholder_copy()`（`inc/placeholders.php`）に登録されており、`confirmed` が `false` の間は公開前チェックに `theme_copy` として出ます。

1. 依頼元に文章を確認してもらう。
2. 承認された文章に、テンプレートの該当箇所を直す（`TODO(仮)` のコメントも消す）。
3. `spc_theme_placeholder_copy()` の該当キーの `confirmed` を `true` にする。
4. `wp spc launch-check` で、その項目が一覧から消えたことを確認する。

### (c) `wp spc seed` の補充の動き

`wp spc seed` は、何度実行しても重複せず、**依頼元が編集した内容は上書きしません。** 既存の仮データ（「仮データ」のチェックが付いたまま）に対して、あとから増えた定義だけを足します。

- メタ（項目）：値がまったく無いキーだけを追加する。チェックボックス項目は補充しない。
- 表示順：0 のままのときだけ、定義の値を入れる。
- 本文：旧シードの `準備中（仮）` と完全に一致するときだけ、新しい本文（見出し＋「（仮）」など）に置き換える。

### (d) 固定ページの本文の使い方（テンプレート側の約束）

- 特殊シミ抜き・高級ダウン・コート・料金・ご利用の流れの本文は、「お知らせ・補足」の欄に出ます。本文が空ならセクションごと出しません。
- 職人・運営会社の本文は「会社概要」の表です。空ならセクションごと出しません。
- 規約3ページの本文は、見出し（h2）＋「（仮）」の骨組みです（特定商取引法に基づく表記は表）。専門家の確認後に依頼元が差し替えます。
- 事例の `spc_case_menu`（関連メニュー）が、下層ページの「関連する施工事例」の絞り込みに使われます。

### (e) 全ページの共通チェック

`tests/e2e/site.spec.ts` が全12URL（トップ、下層ページ、事例一覧、事例詳細1件）について、h1が1つ・`id` の重複なし・見出し階層・パンくずの JSON-LD・NG表現・サイト内リンクの200、375px の横スクロールなし・固定CTA、1280px のヘッダーCTAと相談ブロックを確認します。ページを足したら、`FIXED_PATHS` に追加してください。

# Part B　依頼元（管理画面で更新する方）向け

管理画面（`https://サイトのURL/wp-admin/`）にログインして操作します。画面の左側にメニューが並んでいます。わからないときは、保存する前にいったん手を止めて、保守担当へご連絡ください。

## B-1. ブランド設定の変え方

1. 左のメニューから **「設定」→「ブランド設定」** を開きます。
2. 次の項目を入力します。

| 項目 | 入れるもの |
|---|---|
| ブランド名 | 屋号。決まるまでは「（仮）ブランド名」のままにします |
| LINE追加URL | LINE公式アカウントの友だち追加URL（`https://lin.ee/…` など）。サイトの「写真を送って無料相談」ボタンすべてに反映されます |
| LINE QRコード画像 | パソコンで見た方向けのQRコード。「画像を選択」で、LINE公式アカウントの管理画面から保存した画像を選びます |
| GTMコンテナID | `GTM-` から始まる文字列。計測用です。保守担当から教わった値を入れます |
| FVキャッチの組み方（スマホ） | トップの大きな見出しを、スマホで「縦書き」にするか「横書き」にするか。読みにくいと感じたら「横書き」にします |
| 一次返信の目安 | 相談への最初の返信の目安（例：営業時間内24時間以内）。実際に守れる内容を書いてください。「（仮）」が付いている間は、公開前チェックで「仮のまま」と表示されます |

3. 一番下の **「変更を保存」** を押します。

LINE追加URLとGTMコンテナIDは、形式が正しくないと保存されません。画面の上に赤い枠のエラー（例：「LINE追加URLの形式が正しくないため、変更を保存しませんでした。」）が出て、**それまで保存されていた値のまま**になります。正しい形式（LINE追加URLは `https://lin.ee/…` または `https://line.me/…`、GTMコンテナIDは `GTM-` から始まるID）で入れ直して、もう一度保存してください。

- LINE追加URLを**空欄にして保存**すると、仮のURLに戻ります（エラーにはなりません）。
- GTMコンテナIDを**空欄にして保存**すると、未設定に戻り、計測タグが出なくなります（エラーにはなりません）。

保存後はサイトのボタンを押して、LINEの画面が開くか確認してください。

## B-2. 施工事例を追加する

1. 左のメニュー **「施工事例」→「新規追加」**（画面上は「施工事例を追加」）を開きます。
2. タイトル（例：ウールコートの赤ワインのシミ）と、受付番号・品目・素材・シミの種類・他店での処置・施工内容・仕上がり・作業日数などを入力します。
3. Before画像（施工前）とAfter画像（施工後）を選びます。
4. 「掲載許諾ID」に、お客様から掲載の許可をいただいた記録の番号を入れます（サイトには表示されません）。
5. 「公開」を押します。

守ること：

- **掲載の許可をいただいていないお客様の写真は、絶対に載せません。** 許諾IDが入れられないものは公開しないでください。
- **写真は加工しません。** 同じ角度・同じ明るさで撮り、シミを消す加工や色味の補正はしないでください。
- **仕上がりは正直に書きます。** 「完全には落ちなかった」「薄くなった」など、結果をそのまま書きます。
- 写真に写り込んだブランドのロゴは、ぼかすか、写らないように撮ります。
- お客様のお名前・住所など、個人が特定できる情報は書きません。
- 口コミやお客様の声を、実在しないのに作って載せることは絶対にしません。

## B-3. 料金を更新する

1. 左のメニュー **「料金」** を開き、直したい行をクリックします（新しく足すときは「料金を追加」）。
2. 「区分」で、料金表のどのグループに入れるかを選びます。
3. 「目安金額（円）」には **数字だけ** を入力します（例：15000）。「円」「カンマ」「〜」は入れません。
   - **0 を入れると、サイトには「お見積り」と表示されます。**
   - 「無料」「実費」など、金額の代わりに文字を出したいときは、**「表示用テキスト（任意）」** に入力します。入力すると、目安金額より優先してそのまま表示されます（「〜」は付きません）。空欄にすると、目安金額の表示（0 なら「お見積り」）に戻ります。
4. 「『〜』を付ける」にチェックすると「15,000円〜」の表示になります。
5. 「補足」に、金額の横の一言（例：税込、状態により変動）を入れます。
6. 「更新」を押します。並び順を変えるときは、右側の「順序」の数字を小さいほど上になるよう変えます。

トップページの料金表に出るのは、**送料・手数料も含めて最大50行**です。それより多い場合は、使わなくなった行を下書きに戻すか削除してください。

## B-4. よくある質問を更新する

1. 左のメニュー **「よくある質問」** を開きます（追加は「質問を追加」）。
2. タイトル欄に質問文、本文欄に回答を書きます。
3. 「分類」で、「よくある質問」ページのどの見出しの下に並べるかを選びます。
4. 「トップに表示」にチェックすると、トップページにも表示されます。**トップに出るのは最大5件**です。6件以上チェックしても表示されるのは5件までなので、入れ替えたいときは、先に他の質問のチェックを外してください。

## B-5. 職人を更新する

1. 左のメニュー **「職人」** を開きます（追加は「職人を追加」）。
2. タイトル欄にお名前、「肩書き」「紹介文」を入力します。
3. 右側の **「顔写真」→「顔写真を設定」** で、本人の顔写真を選びます（掲載について本人の同意を得たものだけ）。写真は実際の撮影写真を使い、AI で作った画像は使いません。
4. 「更新」を押します。

トップページに出る職人は**最大4人**です（「順序」の数字が小さい順）。5人以上を登録した場合、トップに出したい方の「順序」を小さくしてください。

## B-6. 「仮データ」のチェックの意味

事例・料金・FAQ・職人の編集画面には「**仮データ（公開前に必ず差し替え）**」というチェックがあります。まだ仮の内容（ダミーの文章・写真・金額）の投稿に付いています。**固定ページ**（特殊シミ抜き・料金・送料・規約など）の編集画面にも、右側の「**公開前チェック**」の欄に同じチェックがあります。

- 一覧画面（固定ページの一覧も含む）の「仮」の列に、印が出ます。
- **本番のサイトでは、仮データの投稿・固定ページは公開されません。** 公開しようとしても下書きに戻され、メッセージが出ます。すでに公開中のものも、本番のサイトには表示されません（固定ページは「ページが見つかりません」になります）。
- 本当の内容に書き換えたら、**そのチェックを外して**から公開してください。固定ページも施工事例などと同じ編集画面（クラシックエディタ）なので、右側の「公開前チェック」のチェックを外して「公開」または「更新」を押せば、そのまま公開されます（先に保存する必要はありません）。
- 画面上部の黒いバーの「仮データ ◯件」が、残っている数です。押すと「サイトヘルス」の画面が開き、「公開前チェック」の欄に残っている項目の一覧が出ます。テーマの写真など、保守担当が差し替える項目も含まれます。0件になれば公開前の準備はおおむね完了です（最終確認は保守担当が行います）。

## B-7. 書いてはいけない表現

お客様に誤解を与える言い方は、景品表示法の観点からも避けます。次のように言い換えてください。

| 書かない | 言い換え例 |
|---|---|
| 必ず落ちる／100%除去／どんなシミも | 落とせる可能性を職人が確認します |
| 完全に元通り | 目立たない状態を目指します（※結果は状態によります） |
| 業界No.1／日本一／最高級 | 根拠がないものは書かない |
| 他店では無理なシミも | 他店で落ちなかったシミのご相談も承ります |
| 今だけ／残りわずか | 使わない |

そのほか：

- 「！」は使わず、丁寧に静かな文体で書きます。
- 分からないことは分からないと書きます（例：「写真だけでは確定できません。現物を拝見して正式にお見積りします」）。
- 件数・満足度などの実績の数字は、根拠の資料があるものだけ載せます。ないものは載せません。

## B-8. 「お知らせ・補足」欄の使い方

特殊シミ抜き・高級ダウン・コート・料金・ご利用の流れの各ページの下のほうに、「お知らせ・補足」の欄があります。臨時のお知らせや、補足したいことがあるときだけ使います。

1. 左のメニュー **「固定ページ」** を開き、直したいページ（例：料金・送料）をクリックします。
2. 本文の欄に、お知らせの文章を書きます。
3. 「更新」を押します。

- 本文が**空のときは、この欄ごとサイトに出ません**。お知らせがなくなったら、本文を消して「更新」を押してください。
- 「！」や、B-7 の書いてはいけない表現は使いません。

## B-9. 会社概要と規約のページを編集する

1. 左のメニュー **「固定ページ」** から、次のページを開きます。
   - 職人・運営会社：本文が、ページの「会社概要」の表になります（運営会社名・所在地・連絡先など）。
   - 規約・法定表示の下の3ページ（利用規約／特定商取引法に基づく表記／個人情報・相談写真の取扱い）：本文が、そのままページの内容になります。
2. 本文を書き換えて、「更新」を押します。
3. 本物の内容にしたら、右側の「公開前チェック」のチェックを外します（B-6 参照）。

- **規約の3ページは、条文を専門家（弁護士・行政書士など）に確認してもらってから差し替えてください。** 仮の見出しと「（仮）」の文章は、確認が済むまで本番では公開されません。
- ページのアドレス（スラッグ）は変えないでください。変えるとページ専用のレイアウトが外れ、共通の簡易な表示になってしまいます。
- 必要な固定ページ（特殊シミ抜き・高級ダウン・コート・料金・送料・職人・運営会社・ご利用の流れ・規約の4ページ）を下書きのままにしていると、公開前チェックで止まります。公開してください。
- 本文に「（仮）」が残っていると、仮データのチェックを外していても公開前チェックで止まります。本物の文章に直して、「（仮）」を消してください。

## B-10. よくある質問の分類が増えました

B-4 の「分類」に、**「シミ抜き」** と **「ダウン・コート」** が加わりました。特殊シミ抜きや高級ダウン・コートに関する質問は、この分類を選ぶと、「よくある質問」ページの該当の見出しの下に並びます。あわせて、**「シミ抜き」は特殊シミ抜きのページ、「ダウン・コート」は高級ダウン・コートのページ** にも表示されます。

## B-11. 事例の「関連メニュー」

施工事例の編集画面の **「関連メニュー（任意）」** で、その事例がどのメニューに関係するかを選びます（特殊シミ抜き／黄ばみ・汗汚れ／高級ダウン／コート・ジャケット）。

- 選んだメニューのページ（特殊シミ抜き、高級ダウン・コート）の「関連する施工事例」に、その事例が出ます。
- **空欄のままなら、下層ページには出ません。** トップと施工事例の一覧には、空欄でも出ます。
