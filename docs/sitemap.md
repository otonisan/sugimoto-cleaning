### 仮データの扱い（WordPress版）

Next.js での「ビルドを止める」に相当する仕組みを、次の3段で実装する。

1. **印を付ける**：仮の投稿（事例・料金・職人など）には、編集画面の「仮データ」チェックボックス（メタキー `_spc_is_placeholder`）を付ける。画面上には DESIGN.md の「仮バッジ」を表示する。
2. **本番では公開・表示しない**：本番環境（`WP_ENVIRONMENT_TYPE=production`）では次のようにする。
   - 「仮データ」が付いた投稿は公開できない。保存時に下書きへ戻し、理由を表示する。
   - テンプレートでも仮データを取得しない。該当するセクションは「0件のとき非表示」のルールで消える。
3. **公開前チェックで止める**：WP-CLI コマンド `wp spc launch-check` は、次のどれかが残っていれば一覧を出して**終了コード1で失敗**する。
   - 仮データ付きの投稿
   - ダミーのLINE URL（`https://lin.ee/PLACEHOLDER`）
   - ブランド名に「（仮）」が含まれている
   - GTM ID が未設定
   - 本番公開（noindex解除・Basic認証解除）は、このチェックが通ってから行う。管理画面の「サイトヘルス」と管理バーにも、残っている件数を表示する。

### LINE URL の管理

- 管理画面「設定 > ブランド設定」の `LINE追加URL` 1か所で管理する（オプション名 `spc_settings[line_url]`）。
- 未設定の場合はダミー `https://lin.ee/PLACEHOLDER` を使う。
- テンプレートからは `spc_line_url()` だけを呼ぶ。URLを直接書かない。

## 2. サイトマップ

```

├─ /stain-removal/        特殊シミ抜き（固定ページ）
│   └─ /stain-removal/[症状]/   ※Phase2：症状別SEOページ（子ページ）

├─ /price/                料金・送料（固定ページ＋料金CPTを表示）
├─ /cases/                施工事例 一覧（CPTアーカイブ）
│   └─ /cases/[slug]/     事例詳細（CPT個別）
├─ /about/                職人・運営会社（固定ページ＋職人CPTを表示）
├─ /guide/                ご利用の流れ / FAQ（固定ページ＋FAQ CPTを表示、#flow / #faq）

（ほかに 404 / wp-sitemap.xml（WordPress標準） / robots.txt）
```

## 4. 計測

GTM のコンテナIDは「ブランド設定」で管理し、テーマが `<head>` と `<body>` 直後にGTMのスニペットを出力する。イベントは `dataLayer.push` で送り、GA4への送信はGTM側で設定する。

| イベント | 発火タイミング | 送る値 | 実装場所 |
|---|---|---|---|
| landing_view | トップ/LP表示時 | `page_type: 'lp'` | テーマのJS → dataLayer |
| line_click | CTAクリック時 | `cta_location` = header / fv / steps / cases / final / sticky / qr_modal | テーマのJS → dataLayer |
| consultation_started | LINEで最初に写真が届いた時点 | ― | **MVPは手動でCRM記録**（Webhookは後で検討） |

- LINE URL への遷移時に UTM を引き継ぐ。相談IDとの突合はCRM側で行う。
- GTM ID が未設定のときはスニペットを出力しない（ローカル・ステージングで誤計測しないため）。
